# 像素特效工坊（FX Forge）· 完整设计方案

> Godot 4.7 编辑器插件：用「预设 + 参数」生成像素风特效动画，一键导出精灵图。

## 0. 背景（Context）

- **需求**：做一个 Godot 特效插件：内置像素特效预设，可调宽度、描边、方向等参数，并导出精灵图。你没有编程/策划经验——设计与开发全部由我完成，你负责在每个阶段试用、提意见。
- **已确认的选择**：先自用、以后可能分享（先做中文界面，代码预留多语言）；四类特效都要（按 战斗打击 → 爆炸与元素 → 魔法与状态 → 环境与通用 的顺序做）；硬边像素与柔光两种风格可切换（默认硬边）；角色尺寸不固定（预设按中等尺寸精调，提供一键整体缩放）。
- **环境**：工作目录 `C:\Users\Chao Yin\Desktop\claude\godot特效插件` 为空，不是 git 仓库；本机 Godot 4.7.1（`C:\Tools\Godot-4.7.1\`，含可无头运行的 `_console.exe`）；你的项目普遍用 Compatibility 渲染器（AMD 核显）；本机装有 Aseprite（`C:\aseprite\build\bin\aseprite.exe`，可命令行调用）。
- **与旧插件 PixelFX 的关系**：PixelFX 是「游戏运行时实时播放」的特效库；本插件是「离线烘焙工具」——在编辑器里调好、产出 PNG 精灵图，任何项目、任何引擎都能用。两者独立、可共存（本插件统一用 `FxForge` 前缀，旧插件是 `Px`）。沿用旧项目踩过的坑：插件内部脚本一律 `preload`；不用 GPU 粒子/着色器；所有功能都做进插件本体，不写外部 Python 工具。

## 1. 产品定义

**一句话**：Godot 顶部多出一个「特效工坊」标签页：左边挑预设，中间看动画，右边拖滑条调参数，点「导出」得到精灵图和能直接拖进游戏的场景。

**使用流程**
1. 启用插件 → 顶部出现「特效工坊」标签（和 2D / 3D / 脚本并列）。
2. 左侧点「火焰斩」→ 中间立刻循环播放。
3. 右侧调宽度、描边、方向（八方向按钮）、配色主题、柔光强度……预览实时刷新。
4. 点「导出」→ 生成 `slash_fire.png`（精灵图）、`slash_fire.tscn`（即用场景）等文件。
5. 在游戏里把 .tscn 拖进场景，或用两行代码在命中点生成，播完自动消失。
6. 「另存为预设」保留你的版本；以后改了参数重新导出，游戏里引用它的地方自动更新。

**小词典**：精灵图 = 把动画每一帧拼成的一张 PNG；SpriteFrames = Godot 存放帧动画的资源；色板 = 一组从暗到亮的颜色，像素画只用这几种颜色；描边 = 外圈一像素宽的深色轮廓；抖动 = 用棋盘格点阵做两种颜色之间的过渡（像素画常用手法）。

## 2. 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 渲染方式 | 纯 GDScript 在 CPU 上逐像素绘制，不用着色器和 GPU 粒子 | 像素级精确（描边、色板、抖动完全可控）；和渲染器无关，核显/Compatibility 不出问题；可无头运行，我能自动出图检查效果；同一套核心以后也能在游戏运行时使用 |
| 特效组织 | 预设 = 若干**图层**，每层是一个**特效模块**（弧光、射线、环、粒子……） | 11 个模块组合出 37 个预设；你也能自己叠图层做新特效 |
| 参数系统 | 每个模块用一张「参数说明表」声明参数（中英文名、范围、默认值、分组、提示），界面自动生成 | 新增特效只需写一个文件；面板统一、每个参数都有中文提示 |
| 界面形态 | 主屏幕标签页 + 自建三栏界面 | 预览区足够大；中文标签与提示完全可控 |
| 预设存储 | 自定义 Resource（`.tres`），参数存在字典里，带版本号 | 双击 .tres 直接在工坊里打开；以后参数增删不会让旧预设失效 |
| 流畅度 | 多线程并行渲染各帧；拖动滑条时只重算当前帧，松手再重算整段 | 128px 级画布也有实时手感 |
| 导出 | PNG 精灵图 + JSON（Aseprite 格式）+ SpriteFrames + 即用场景（不依赖插件）+ 可选单帧序列 / GIF | Godot 里直接用；Aseprite 可二次修改；其他引擎也能读 |

## 4. 渲染管线

```
预设（全局参数 + 图层列表）
 → 每层：模块.prepare(参数, 种子)        主线程，生成不可变数据（粒子表、闪电折线、噪声表……）
 → 每帧（并行）：模块.render(画布, t)     → 强度图（0~1 浮点）
 → 着色：强度 → 色板阶梯（可 Bayer 抖动）→ 透明度（硬边 = 0/1；柔光 = 分级半透明）
 → 按顺序合成图层
 → 描边（外/内/选择性；宽 1~3；方角/圆角；可指定哪些图层参与）
 → 清理孤立像素 → 柔光外晕（可选）→ 水平/垂直翻转
 → 每像素一个整数颜色 → 一次性转成 Image（RGBA8）
```

- 在像素中心采样；方向旋转作用在「采样坐标」上而不是旋转成品图，所以任何角度都是干净的像素线条。
- 时间：一次性特效取 t = (i+0.5)/N（首尾不出空帧）；循环特效取 t = i/N，且噪声、粒子在时间上周期化，最后一帧无缝接回第一帧。
- 每层的随机种子由全局种子派生：同参数同种子，输出逐字节一致。
- 只遍历包围盒内的像素；查表代替逐像素计算（强度→色阶、Bayer 阈值、色阶→颜色）。

## 5. 参数体系

### 5.1 全局参数（所有预设共有）

| 分组 | 参数 |
|---|---|
| 画布与时间 | 画布宽/高、尺寸档（小 ×0.5 / 中 ×1 / 大 ×2）、整体缩放（0.25~4，几何参数与画布一起缩放，描边宽度不变）、帧数、帧率、循环、随机种子（🎲）、锚点（中心 / 底部中心 / 自定义） |
| 方向 | 方向角（0~359°，3×3 八方向快捷按钮）、水平翻转、垂直翻转 |
| 外观 | 配色主题（火/冰/雷/毒/圣/暗/血/自然/水/奥术/钢/烟……一键给所有图层换色）、主/辅/烟尘三个色板槽、柔光强度（0 = 纯硬边）、透明度层级（1~4）、抖动（无 / 2×2 / 4×4 + 强度）、消散方式（抖动溶解 / 收缩 / 变暗 / 淡出） |
| 描边 | 模式（无 / 外 / 内 / 选择性）、宽度 1~3、颜色（固定色 / 色板最暗色 / 自动加深）、拐角（方 / 圆） |
| 清理 | 去除孤立像素、最小团块大小 |

### 5.2 图层参数
每层：模块类型、名称、显示/独显、色板槽、起止时间（占时间轴的比例，例如烟雾 30%~100%）、跟随全局方向 + 角度偏移、位置偏移、是否参与描边，以及模块自己的参数（见第 6 节）。参数分「常用」和「高级」，默认只显示常用。

### 5.3 参数说明表（开发约定）
```gdscript
P.num("thickness", "宽度", "Width", 1, 64, 8, {unit = "px", scale = true, group = "形状", tip = "刀光最粗处的宽度"})
```
类型：num / int / bool / enum / color / angle / palette_slot。`scale = true` 的参数跟随整体缩放。界面、默认值、校验、预设迁移都由这张表派生。

### 5.4 色板
约 16 套内置色板（自行设计的 4~7 阶色相偏移色阶，无版权问题）；配色主题 = 主/辅/烟尘三色板组合；「单色生成色阶」（选一个颜色，自动生成带冷暖偏移的色阶）；后期支持导入 Lospec `.hex` / `.gpl` 和调色板 PNG。

## 9. 导出

**导出对话框**：文件名（默认英文 id）、目录（默认 `res://fx_exports/`）、布局（单行 / 网格 / 自动 + 列数）、间距/边距、裁掉空白、放大倍数（1~4×，分享用）、方向批量（无 / 左右 / 4 向 / 8 向，每个方向一行）、变体数（不同种子 N 份）、导出内容勾选、场景混合模式（正常 / 发光叠加）。

| 文件 | 说明 |
|---|---|
| `name.png` | 精灵图 |
| `name.json` | Aseprite 数组格式（帧矩形、时长、frameTags、锚点），其他引擎和工具可读 |
| `name_frames.tres` | SpriteFrames：每个方向/变体一个动画，帧率与循环已设好 |
| `name.tscn` | 即用场景：AnimatedSprite2D（最近邻过滤、锚点对齐、自动播放）。场景内嵌一小段运行时脚本：一次性特效播完自动删除，可勾选随机水平翻转。**不依赖插件**，删掉插件也能用；这段脚本不在编辑器里运行，预览动画时不会误删节点 |
| `name_000.png …`（可选） | 单帧序列，Aseprite 可直接作为动画打开 |
| `name.gif`（可选） | 预览、分享用（Godot 没有内置 GIF 写出，插件自带编码器） |
| `name.fxforge.tres`（默认开） | 本次导出所用的预设副本，以后双击打开、修改后再导 |

- 同名文件重新导出会原地覆盖（先确认）；已存在的 SpriteFrames 原地更新，游戏中引用它的场景自动跟着变。
- **导出内部顺序**（按 4.7 源码核查结果固定）：等编辑器空闲（没在扫描/导入）→ 写 PNG → 通知文件系统并立即导入 → 加载贴图 → 生成/更新 SpriteFrames → 打包并保存场景；全程防止重复触发。任何一步失败都保留已写出的 PNG，并给出中文提示。

## 10. 游戏中使用（会写进中文使用手册）

```gdscript
var fx = preload("res://fx_exports/slash_fire.tscn").instantiate()
fx.position = hit_position
add_child(fx)   # 播完自动消失
```

场景的检查器里可以勾选「播完自动删除」「随机水平翻转」；循环类特效（火焰、光环）会一直播放，直到你删除它。

## 11. 开发里程碑

你不需要安装任何东西（Godot 4.7.1 已在本机）。每个里程碑结束时：测试全部通过 → 我渲染预设画廊图片逐张自查 → 给你一份简短说明和需要试用的点 → 本地 git 提交一次（不推送）。

## 12. 验证方式

以下 `godot` 指 `C:\Tools\Godot-4.7.1\Godot_v4.7.1-stable_win64_console.exe`；不加 `-d`（调试器会停在第一个错误等键盘输入）。

- **首次准备**：新工程先跑一次 `godot --headless --path . --import`，生成全局类缓存和导入文件。
- **单元测试（无头）**：`godot --headless --path . --script res://tests/run_tests.gd`。测试失败时脚本主动以退出码 1 结束；同时检索日志里的 `SCRIPT ERROR` / `Parse Error` / `ERROR:`（运行时脚本错误不会改变退出码，所以两者都要看）。覆盖：色板量化与抖动阈值、描边（单像素 → 十字/方块）、孤立像素清理、打包矩形不重叠不越界、JSON 字段、同种子逐字节一致、循环首尾连续、所有内置预设可加载且参数完整、每个预设的渲染耗时（输出耗时表）。只检查 Image 和字节数据（无头模式下贴图是空壳）。
- **预设画廊**：`godot --headless --path . --script res://tests/render_gallery.gd`，把每个预设渲染成放大的精灵图和一张总览图，我逐张查看并调整美术效果。
- **插件加载冒烟**：把工程复制到临时目录再测（编辑器运行会改写 .godot / .import / .uid，加载失败时还可能把插件从 project.godot 里移除）：`godot --headless --editor --path <副本> --quit`，检索日志里有没有 `Unable to load addon script` 等错误。
- **编辑器内导出自检**：在副本里跑 `godot --headless --editor --path <副本> -- --fxforge-selftest`：插件识别这个参数，等文件扫描结束后导出一个预设，校验 PNG、JSON、SpriteFrames（帧数/帧率/循环）、.tscn 能加载并实例化，再按结果退出。
- **Aseprite 兼容（可选）**：用本机 Aseprite 命令行打开导出的单帧序列，确认识别成同样帧数的动画。
- **界面与游戏内效果**：启动编辑器截图核对界面；运行 demo 场景，确认导出的 .tscn 在游戏中正确播放、播完消失、像素不模糊。

## 13. 风险与对策

- **GDScript 速度（大画布）** → 估算：128×128×16 帧整段重算约 0.05~0.12 秒，256×256×24 帧约 0.3~0.6 秒，拖动时单帧 256² 约 0.1 秒（M1 实测确认）。对策：只算包围盒、查表、高优先级多线程、拖动只算当前帧、新请求打断旧渲染、画布上限 512。
- **插件脚本出错被 Godot 自动禁用** → 遵守第 14 节硬规则；plugin.gd 保持极简；每次改动后跑加载冒烟。
- **刚写出的 PNG 还没导入就被引用** → 固定导出顺序（第 9 节）。
- **美术效果是核心价值** → 画廊图迭代 + 每个里程碑听你的反馈。
- **多线程隐患** → 工作线程只读不可变数据、只写自己那一帧；保留「单线程模式」调试开关。

## 14. 开发硬规则（实现时必须遵守，来自 4.7 源码核查和旧项目踩坑）

1. 插件脚本全部 `@tool`（即用场景里的运行时脚本除外）；重写引擎方法时写全类型签名，每条分支都 return（4.7 起漏写会解析失败、插件被禁用）。
2. 插件内部互相引用用 `preload`；插件端脚本不预加载图片、场景等需要导入的资源。
3. `core/` 不碰任何 Editor 接口，保证可无头测试、可在游戏运行时使用；编辑器功能只放在 `editor/` 和 `export/`。
4. 多线程用高优先级分组任务；渲染任务对象在完成前保持引用；每个任务只等待一次；插件关闭前先等正在跑的任务结束。
5. 工作线程不碰共享随机数生成器、Resource、贴图或节点；随机表在 prepare 阶段预生成，或每帧用独立种子。
6. 逐像素循环里不调用函数、不查字典、不构造 Vector2/Color；颜色查表后写入 PackedInt32Array，最后一次性转成 Image。
7. 预设：`load()` 拿到的是共享缓存，编辑前先深拷贝；内置预设只读；加载时按参数说明表补齐/校正（整数参数取整、枚举存字符串 id）；脚本不预加载使用自身的 .tres（避免循环加载）。
8. 撤销/重做挂在一个 RefCounted 会话对象上（进入全局历史）。
9. 插件的 `.uid` 文件一并提交（内置预设靠 UID 找到预设脚本）。
